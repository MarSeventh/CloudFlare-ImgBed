# 回收站与两层删除权限

普通删除（包括替换成功后选择删除源文件）仅移入回收站，不清理源文件的底层存储内容。回收站不会定时清空，文件继续占用存储空间。

| 操作 | Token 权限 | 接口 |
| --- | --- | --- |
| 浏览回收站 | 文件浏览 `list` | `GET /api/manage/trash?cursor=...` |
| 移入回收站 | 文件删除 `delete` | `DELETE /api/manage/delete/{pathOrFixedId}` |
| 恢复 | 文件删除 `delete` | `POST /api/manage/trash/{id}/restore` |
| 永久删除 | 永久删除 `purge` | `DELETE /api/manage/trash/{id}` |
| 替换并移走源文件 | 内容替换 `replace` + 文件删除 `delete` | 原替换接口，`deleteSource:true` |

## 与上游的接口差异（升级必读）

上游 `MarSeventh/CloudFlare-ImgBed` 的 `DELETE /api/manage/delete/{path}` 会直接删除底层存储内容。本仓库中同一接口改为**移入回收站**，响应仍为 `success`，但存储空间不会释放。依赖旧行为清理空间的脚本或客户端需要改为两步：

1. `DELETE /api/manage/delete/{pathOrFixedId}`：移入回收站，回收站 ID 即文件的固定 ID（`f_…`）。
2. `DELETE /api/manage/trash/{id}`：永久删除，Token 需额外具备 `purge` 权限。

旧 Token 的 `delete` 权限不会自动获得 `purge`，因此升级后原有删除脚本只会把文件移入回收站，需要管理员为对应 Token 明确勾选“永久删除”。

七项授权相互独立。永久删除不隐含普通删除，普通删除和系统管理也不直接获得永久删除。旧 Token 不会自动新增 `purge`；需要管理员明确编辑授权。管理员登录会话保持完整管理能力。系统管理能创建 Token，仍然是高权限。

## 数据与恢复

回收站使用 `manage@trash@{固定ID}` 保存原路径、完整文件记录、删除时间与状态，先保存恢复副本，再移除活动文件记录。固定 ID 与历史路径注册保留，防止旧链接被新上传文件占用。文件在回收站时，从活动列表移除，固定链接和历史路径返回不存在；恢复后沿用原路径、元数据和固定 ID。恢复不会覆盖同名活动文件。

目录删除逐个归档文件，失败的文件保留；全部成功后另存已登记的空目录结构。回收站中的文件、目录结构分别恢复，不会因恢复目录而意外恢复全部子文件。列表每页最多 100 个项目，继续使用返回的 `cursor`，即使某页为空也须继续到 `null`。搜索只针对页面已加载的数据。

永久删除只接收回收站 ID，活动文件不能直接永久删除。清理前检查活动存储引用；底层清理失败保留回收站记录供重试。开始物理清理后的项目不允许恢复，因为分片可能已经部分删除。完成后只保留不含内容、凭据或恢复数据的最小墓碑，防止旧索引再次显示文件；该墓碑不能恢复。

R2、S3、WebDAV、Discord、HuggingFace 会调用渠道清理接口。Telegram、Telegraph 与外链不提供可用的底层删除操作，此类永久删除仅不可恢复地移除图床记录，不保证第三方文件消失。HuggingFace 的仓库历史、存储供应商的版本或备份不在图床删除保证范围内。接口的 `storageDeleted` 表示是否执行了受支持的存储清理。

回收站不是替换的版本历史：目标内容仍然被覆盖，替换的旧目标内容仍按原替换逻辑清理。此次可恢复的是选择移走的源文件。重命名、移动的旧对象清理和失败副本回滚也不属于用户的文件删除权限。

## 一致性与运维

永久删除和本地文件替换在清理旧内容前会检查其他记录是否仍引用同一存储对象。检查按列表分页进行（每 1000 条一次列表请求）：活动文件直接使用列表元数据，只有 Discord 分片文件需要单独读取；回收站记录在列表元数据中保存状态、渠道和存储摘要，无关记录不读取正文。本功能上线前写入的回收站记录没有这些摘要，仍会逐条读取。检查失败时保留旧内容并返回警告。

单实例操作互斥，写入前检查快照；KV 最终一致性和数据库/对象存储间没有分布式事务，不能保证跨实例原子互斥。客户端必须串行执行同一文件的恢复、删除、移动、替换，尤其不要并发恢复和永久删除。CDN 缓存清理依赖已有 Cloudflare 凭据；浏览器或第三方已缓存/下载的内容无法撤回。

回收站与活动文件都应纳入备份。升级没有自动迁移或批量删除操作，也无法恢复上线前已物理删除的文件。测试使用本地 KV、真实 SQLite 的 D1 适配模拟及第三方存储模拟；不要在生产文件上进行永久删除验收。
