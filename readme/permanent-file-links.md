# 固定 ID 与永久链接

新入库文件会分配只读 `FixedId`，例如 `f_0123456789abcdef0123456789abcdef`。永久链接为 `/file/{FixedId}`，不带文件名或扩展名；服务器继续根据文件记录返回原文件及正确的 Content-Type。

## 使用

- 在管理后台打开文件详情，顶部“固定 ID”标签可查看并复制只读 ID。原始链接已等于永久地址时不重复展示；使用不同的自定义前缀、外链或旧路径时，顶部另显示“永久链接”标签。下方表格不重复展示 ID 或永久链接。
- 文件路径由所在文件夹与文件名组成。详情页只保留“编辑”入口：保存文件名时同步更新路径末尾；更改所在文件夹只能通过“移动”，改名接口也会拒绝跨目录操作。
- 修改显示名称、标签或移动目录，不会修改已分配的固定 ID。网页、Bot 与分片上传返回固定地址；后台复制链接在已有固定 ID 时优先使用它。
- 旧文件第一次打开详情，或第一次修改/移动时初始化身份。当时的路径及此后的历史路径会保留为别名，始终解析到同一条当前记录；不会创建重复文件或重复统计。
- 升级前已经因改名/移动而丢失的历史路径无法自动找回。本功能兼容的是升级时仍然存在的文件地址及此后的地址。
- Telegram 中的 `TgFileId` 是存储凭据，与图床固定 ID 分开保留。

## 文件名统一

管理后台首次进入时会调用需要管理权限的 `/api/manage/normalizeNames`，分批将历史文件路径末尾统一为显示名称。进度保存在数据库中，页面关闭后下次进入继续；不修改文件夹、固定 ID 或文件内容。全部整理完成前请保持页面打开以便尽快处理完毕。

同目录重名会保留两个文件，为后一个名称补上 ` (2)`、` (3)` 等序号，并同步显示名称。非法名称、旧版不支持移动的存储渠道或其他失败项目保留原状并显示错误，可修正后点击重试。不会覆盖目标文件。

网页和 Bot 新上传默认按文件名建立路径，重复名称补序号；不再提供时间戳、随机路径名等独立命名选项。永久访问地址仍使用固定 ID。恢复包含旧命名方式的备份后，会重新安排名称统一。

`PATCH /api/manage/metadata/{path}` 的 `FileName` 会同时重命名文件路径；响应中的 `newFileId` 是操作后的当前路径。兼容原有 `/api/manage/rename/{path}`，但只接受同目录的 `newFileId` 或单独的 `newFileName`，不允许将改名当作移动操作。

## 数据与访问规则

图片加载后，详情页使用浏览器实际解码的原始像素宽、高（不是预览框的 CSS 尺寸）显示尺寸及方向。记录缺失一边或与实际尺寸不一致时，管理端会将完整宽、高写回元数据。保存失败时仍展示本次读取的尺寸；无法解码的图片保留已知的有效尺寸，不伪造数据。自动补全只更新 `Width`、`Height`，不会修改名称、目录、标签或固定 ID。

固定 ID 存在文件元数据中；ID 到当前路径的映射、历史地址映射存于 `manage@identity@…` 设置键，兼容 KV/D1，不需要修改数据库表结构。它们不会进入文件列表或容量统计。旧文件按需初始化，不执行全库迁移。

删除文件仍会令所有引用失效；已有历史路径会保留占用，防止旧链接意外显示另一个文件。返回自己拥有的历史路径可以继续操作。重复文件名冲突会拒绝操作。

永久地址与历史地址都经过同一读取接口，继续应用文件黑白名单、审查与原有访问规则。改动时的 Cloudflare 缓存清理会同时覆盖固定地址和历史地址，仍需原有缓存清理凭据正确配置；客户端已经缓存的图片无法从服务器强制撤回。

使用“备份全部数据”（文件和系统设置）保留完整历史地址映射；仅备份文件元数据可以恢复固定 ID，但不足以恢复所有历史别名。KV 本身具有最终一致性，移动后映射传播期间可能短暂不可见；本改动不提供跨对象存储和数据库的事务。

```sh
node --test tests/file-identity.test.mjs tests/telegram-webhook.test.mjs
node --import ./deploy/server/register.mjs --test tests/permanent-link-integration.test.mjs
npx wrangler pages functions build functions --outdir .wrangler/identity-build
```

测试包含 KV/D1 身份持久化、连续改名/移动后的旧链接、删除与路径复用保护，以及真实读取/改名/移动处理函数在模拟 Telegram 服务下返回相同图片字节和 Content-Type。

## 替换文件内容

单文件操作支持保留目标原链接、用另一个已入库文件的内容替换，详见 [单文件替换](file-replacement.md)。
